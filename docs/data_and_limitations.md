# Данные, допущения и ограничения

## 1. Назначение данных

Синтетические данные используются для разработки и демонстрации прототипа. Они не являются банковской историей реальных заёмщиков и не должны трактоваться как репрезентативная выборка малого бизнеса.

## 2. Данные компании и заявки

Для сценария оценки риска могут использоваться сведения о возрасте и отрасли компании, выручке, прибыли, существующей задолженности, кредитной истории, сумме и цели кредита. Фактический состав определяется текущей реализацией генератора и модели.

Для каждого признака необходимо фиксировать:
- бизнес-определение;
- тип и единицы измерения;
- источник;
- допустимые значения;
- обработку пропусков;
- момент времени, на который признак известен.

## 3. Предотвращение утечки данных

При подготовке обучающего набора необходимо исключить признаки, которые прямо или косвенно раскрывают целевую категорию. Все преобразования, требующие обучения на данных, следует подбирать только на обучающей выборке.

Разделение train/test должно соответствовать предполагаемому использованию модели. Если данные имеют временную структуру, следует рассмотреть временное разделение.

## 4. Ограничения прототипа

1. **Синтетичность:** распределения признаков и связь с целевой переменной задаются генератором.
2. **Ограниченная внешняя валидность:** метрики на синтетике не гарантируют качества на реальных компаниях.
3. **Необходимость бизнес-политики:** категория риска не является сама по себе кредитным решением.
4. **Объяснимость:** для реального финансового сценария пользователю и сотруднику банка может требоваться объяснение факторов прогноза.
5. **Безопасность:** реальные финансовые и персональные данные требуют контроля доступа, безопасного хранения и минимизации логирования.
6. **Мониторинг:** при реальном использовании необходимо отслеживать качество, дрейф данных и изменения долей классов.

## 5. Что требуется для перехода к пилоту

- валидировать модель на независимых исторических данных;
- согласовать целевое событие и горизонт риска с бизнесом;
- проверить качество и калибровку вероятностей;
- оценить качество отдельно для значимых сегментов;
- документировать версии данных, признаков и модели;
- реализовать мониторинг и аудит;
- провести проверку безопасности и соответствия требованиям организации;
- предусмотреть экспертное рассмотрение спорных случаев.
