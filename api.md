# API и интеграция

## 1. Назначение

Этот документ описывает принципы взаимодействия интерфейса, backend и ML-компонента. Точные маршруты и схемы необходимо извлекать из фактической реализации.

## 2. Где проверить контракт

Перед добавлением конкретных endpoint'ов проверьте:

- исходный код маршрутов в `backend/`;
- Pydantic-схемы или другие модели валидации;
- код вызова ML-модели в `ml/` и/или `backend/`;
- конфигурацию приложения в Docker Compose;
- OpenAPI-описание, если оно генерируется приложением.

Если backend использует FastAPI, после запуска обычно доступна интерактивная документация по адресу `/docs`, а альтернативная документация — по `/redoc`. Наличие и адрес этих страниц следует подтвердить по конфигурации приложения.

## 3. Логический контракт скоринга

Для выполнения скоринга приложению концептуально нужны:

### Входные данные

- параметры компании;
- параметры кредитной заявки;
- категории признаков в ожидаемом моделью формате.

### Результат

- предсказанная категория риска;
- вероятности классов, если они рассчитываются и возвращаются;
- информация об ошибке, если входные данные не прошли валидацию или модель недоступна.

Эти поля описывают ожидаемую функциональность, но не заменяют реальную Pydantic-схему запроса/ответа.

## 4. Пример обмена данными

Ниже приведён псевдопример для обсуждения контракта. Он не предназначен для выполнения без сверки с исходным кодом.

Запрос может содержать сумму кредита, возраст компании, отрасль, выручку, прибыль, существующую задолженность, статус кредитной истории и цель кредита. Сервер должен проверить типы, допустимые диапазоны и наличие обязательных полей до передачи признаков в модель.

Ответ может содержать класс риска и вероятности четырёх классов. Порядок классов должен браться из сохранённой модели, а не предполагаться клиентом.

## 5. Ошибки

При документировании реального API укажите фактически реализованные HTTP-коды и схемы ошибок. В частности, проверьте обработку:

- отсутствующих обязательных полей;
- некорректных типов и значений;
- неизвестных категорий;
- отсутствующего файла модели;
- ошибок инференса;
- внутренних ошибок сервера.

Не возвращайте клиенту traceback, секреты или содержимое внутренних файлов.
