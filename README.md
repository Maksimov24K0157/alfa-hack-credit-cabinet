## О проекте

«Умный кредитный кабинет» — прототип цифрового интерфейса, в котором представитель бизнеса может работать со сценарием оформления кредита, а система — оценивать риск компании с помощью модели машинного обучения.

ML-компонент использует CatBoost для многоклассовой классификации. Модель относит заявку к одному из предусмотренных уровней риска:

- `low_risk` — низкий риск;
- `medium_risk` — средний риск;
- `high_risk` — высокий риск;
- `very_high_risk` — очень высокий риск.

Точные бизнес-действия, соответствующие каждому классу риска, должны задаваться кредитной политикой приложения. Класс модели сам по себе не является решением об одобрении или отказе.

## Возможности

- пользовательский интерфейс кредитного кабинета;
- серверная часть приложения;
- ML-компонент для оценки уровня кредитного риска;
- контейнеризация проекта с помощью Docker Compose;
- автоматизированные тесты в каталоге `tests`.

Перечень выше описывает компоненты проекта на уровне репозитория. Конкретный состав пользовательских сценариев и доступных API-операций следует сверять с текущим кодом приложения.

## Архитектура

Репозиторий разделён на несколько основных частей:

| Компонент | Назначение |
|---|---|
| `frontend/` | Пользовательский интерфейс |
| `backend/` | Серверная логика и обработка запросов |
| `ml/` | Данные, обучение и использование ML-модели |
| `docs/` | Документация проекта |
| `tests/` | Автоматизированные тесты |
| `docker-compose.yml` | Конфигурация запуска контейнеров |

Предполагаемый пользовательский поток: пользователь вводит параметры заявки → сервер получает и проверяет данные → ML-компонент формирует прогноз → результат возвращается приложению для отображения. Конкретные границы сервисов и способ вызова модели необходимо сверять с реализацией.

Подробности: [`docs/architecture.md`](docs/architecture.md).

## Технологии

Подтверждённые по описанию и материалам проекта направления:

- **Python** — ML-часть и серверная логика;
- **CatBoost** — многоклассовая модель градиентного бустинга;
- **Docker Compose** — запуск компонентов в контейнерах.

Фреймворки frontend/backend, версии библиотек, СУБД и конкретные команды локального запуска следует брать из `package.json`, файлов зависимостей, Dockerfile и `docker-compose.yml`, а не фиксировать в документации без проверки.

## Запуск

### Вариант 1. Docker Compose

Установите Git и Docker Desktop (Windows/macOS) либо Docker Engine и Docker Compose (Linux).

```bash
git clone https://github.com/Maksimov24K0157/alfa-hack-credit-cabinet.git
cd alfa-hack-credit-cabinet
docker compose up --build
```

Если установленная версия Docker использует старую команду Compose, может работать `docker-compose up --build`.

После запуска смотрите опубликованные порты в `docker-compose.yml`. Адреса интерфейса и API нельзя надёжно указать без проверки текущей конфигурации.

Остановка:

```bash
docker compose down
```

### Вариант 2. Локальный запуск компонентов

Команды локального запуска зависят от файлов зависимостей и точек входа в текущей версии проекта. Перед запуском проверьте:

- `backend/` — README, `requirements.txt`/`pyproject.toml`, Dockerfile и модуль приложения;
- `frontend/` — `package.json` и scripts;
- `ml/` — файл зависимостей, скрипт обучения и способ загрузки модели.

Не запускайте одновременно локальные и контейнерные экземпляры на одних портах.

## Работа ML-компонента

ML-модель выполняет многоклассовую классификацию уровня риска компании. В ходе разработки использовались синтетические данные; поэтому качество на них не гарантирует аналогичное качество на реальных клиентах банка.

Общий процесс ML-разработки:

1. подготовка и проверка признаков;
2. разделение данных на обучающую и тестовую выборки;
3. обучение CatBoost;
4. оценка качества по классам;
5. сохранение модели;
6. загрузка модели и получение прогноза для новых входных данных.

Состав признаков, метрики, параметры обучения и путь к сохранённой модели должны соответствовать текущему коду и артефактам проекта. См. [`docs/ml_model.md`](docs/ml_model.md).
